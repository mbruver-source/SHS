# Zusätzliche Abhängigkeiten NUR für den Web-Server der geplanten Podman/Web-Version
# (app_web.py, V1: Ergebniseingabe über einen gemeinsamen Zugangscode je Termin - siehe
# Modul-Docstring dort und Fortschritt.md für den Hintergrund).
#
# Bewusst getrennt sowohl von requirements.txt (Desktop-Installer, siehe dortiger
# Kommentar in requirements-postgres.txt) als auch von requirements-postgres.txt selbst
# (nur der Datenbanktreiber, wird z. B. auch für die Postgres-Tests in der CI gebraucht,
# ohne dass dafür gleich Flask mitinstalliert werden müsste). Zum Einrichten des
# Web-Servers werden BEIDE Dateien gebraucht:
#   pip install -r requirements-postgres.txt -r requirements-web.txt
#
# Flask + die eingebauten Jinja2-Templates (templates/*.html) statt eines
# JavaScript-Frontends, u. a. weil die Web-Version bewusst nur im lokalen
# Vereins-Netzwerk laufen soll (kein verlässlicher Internetzugang am Prüfungstag
# vorausgesetzt) - ein serverseitig gerenderter Ansatz ohne externe CDN-Abhängigkeiten
# passt dazu am einfachsten. Der eingebaute Flask-Entwicklungsserver (app.run(), siehe
# app_web.py) ist dabei nur für lokale Tests gedacht.
#
# Obergrenzen (Codeprüfung 22.09., G12): jeweils "<" die nächste Major-Version NACH der
# aktuell (Stand 22.09.2026) neuesten (Flask 3.1.x, waitress 3.0.x), damit
# ein Major-Sprung nicht unbemerkt ins Container-Image gelangt - Untergrenzen unverändert.
Flask>=3.0,<4

# WSGI-Server für den echten Einsatz im Podman-Container (siehe Containerfile) - ersetzt
# dort den Flask-Entwicklungsserver. Reine Python-Abhängigkeit (kein C-Compiler im Image
# nötig, anders als z. B. gunicorn unter manchen Umgebungen).
waitress>=3.0,<4
